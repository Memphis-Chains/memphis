## Investigation plan (tier-2 read-only, then write)

1. **Download the artifact** — `nightly-crystal.json` has structured test results. Cross-check with the trimmed stdout to recover test names + assertion text.
2. **Locate the test source** — search for `crystal` in the repo. Likely under `crates/memphis-runtime/tests/` or similar.
3. **Read the panic** — what assertion fails? Is it expecting a specific on-disk state, a chain hash, a config schema, or a specific runtime version?
4. **Diff against last green run** — find the most recent `nightly-crystal` run that succeeded and diff:
   - which commits landed on `main` between green and red?
   - did any of those touch the crystal-pass test, the runtime version under test, or its fixtures?
5. **Hypothesis space** (ranked by likelihood based on naming):
   - (a) Runtime version drift — the crystal test pins a specific memphis version in fixture, and a recent release changed behavior.
   - (b) Fixture staleness — golden file in `fixtures/crystal/` was regenerated by an older version with different formatting.
   - (c) Chain state pollution — nightly runs against a real chain (`~/.memphis/chains/` or workspace), and prior incomplete runs left bad state.
   - (d) Test isolation — tests share a global (clock, RNG, env var) and order-dependence crept in.
6. **Reproduce locally** — `cargo test --workspace --test crystal` or whichever target. Then bisect.
