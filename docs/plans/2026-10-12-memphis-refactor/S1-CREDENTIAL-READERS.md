The new [surface fixture](../../../tests/integration/vault-reader-surfaces.test.ts)
uses the same encrypted data through named/raw/bounded facades, HTTP, CLI, MCP and
the native reader. Readable exports intentionally return synthetic plaintext after
mocked authorization; failures must expose only safe classification. It covers
missing/malformed/authenticated state, unsupported version, missing pepper, entry
authentication and invalid UTF-8, plus the distinct missing-key/raw-entry case.
Entry-store corruption/fingerprint/order and
journal/process races have separate parity/recovery evidence.

Raw decrypt is an explicit request to decrypt the supplied entry; it does not
select a current stored entry. Metadata listing does not prove decryption. A
missing stored key may be a normal not-found result in a listing/export facade
and an exception when a bounded credential operation requires it. These operations
must not be forced into an identical success shape merely to make a table pass.

Full S1.4/S1.7 acceptance still requires reconciliation of the complete stated
matrix at a selected release revision. The local source is mixed and uncommitted;
see [EXECUTION](EXECUTION.md) for deployed slices and outstanding gates.
