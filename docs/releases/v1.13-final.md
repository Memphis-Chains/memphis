## TL;DR

Memphis 1.13 is the first release where the runtime is **sovereign, observable,
and self-recovering** out of the box:

- 10 chain-backed memory stores with cryptographic integrity verification.
- Encrypted vault for operator secrets with a tiered capability boundary.
- A Rust NAPI bridge for hot path operations (chain writes, embeddings).
- A native Rust operator cockpit (`memphis serve`) plus Telegram gateway.
- Three production skills shipping with the runtime.
- A real public site rebuilt end-to-end with Memphis-powered automation.

No `tail -f /var/log/syslog`. No third-party telemetry. No cloud lock-in.

## What's in 1.13

### 1. Chain-backed memory

Memphis stores operator state in **ten append-only chains**, each with its
own Merkle-style hash linkage. Block writes go through a Rust NAPI bridge
that performs atomic `tmp + rename` and verifies the just-written file
matches the payload sent to write — a defence against partial-write and
serializer-race corruption observed in earlier versions.

Chains ship in 1.13: `journal`, `decisions`, `reflections`, `patterns`,
`cases`, `collective`, `system`, `soul`, `insights`, plus the embedded
`memphis.db` for high-frequency exact search.

### 2. Encrypted vault with tiered capabilities

Secrets (operator tokens, API keys, memory archives) live in an AES-GCM
vault at `~/.memphis/vault-entries.json`. Three capability tiers:

| Tier | Auth | Scope |
| --- | --- | --- |
| 0 | none | soul memory, journal, recall, health, case entries |
| 1 | API token | config, channels, providers, vault metadata |
| 2 | vault passphrase | source code, tools, handlers (snapshot + branch + tests) |

Tier 2 is the production safety valve: any self-modification is gated on a
git snapshot, a branch checkout, and a passing test run. Rollback is one
command.

### 3. Native operator cockpit

`memphis serve` exposes:

- HTTP gateway at `http://127.0.0.1:3000` for the Telegram channel.
- A Rust TUI as the authoritative operator surface (`memphis term` or
  systemd-attach). The TUI and Telegram surfaces route through the same
  host transport — there is exactly one operator.
- Systemd unit (`memphis.service`) with a `memphis-warmup.service` that
  pre-loads LLM and embedding models so the first turn after boot is
  fast. GPU with auto-CPU-fallback (defensive for small VRAM GPUs).

### 4. Three new skills shipping with the runtime

1. **`lhpl-site-edit` v2.0.1** — server-side edit, deploy, and rollback
   for `lh.pl` static sites. One skill replaces a half-dozen ad-hoc
   scripts. Subcommand `discover` replaces the standalone
   `lhpl-site-discovery` skill.
2. **`vault-secret-add` v1.0.0** — encrypt + add vault entries. Matches
   the Rust vault algorithm byte-for-byte.
3. **`lhpl-ssh-key-vault` v1.0.0** — SSH key rotation via the vault with
   `mode 0600` tmpfiles. No private keys ever touch the working tree in
   plaintext.

### 5. marcin-kukla.pl rebuild (dogfooding)

The operator's own landing page — `marcin-kukla.pl` — was rebuilt as
end-to-end proof that Memphis skills can drive a real production site:

- Direct phone number, Calendly link, and contact CTA above the fold.
- End-to-end SSH-key-vault ingest verified: SSH to `serwer437043.lh.pl`

  `109aa6fb54c9b3b73d0056078829d21a`).

### 6. Observability and self-recovery

- `scripts/wal-checkpoint.mjs` + systemd timer — runs
  `PRAGMA wal_checkpoint(TRUNCATE)` every 6 hours with jitter.
- `scripts/chain-integrity-sweep.mjs` + hourly systemd timer — detects
  chain corruption within an hour instead of when a TUI session hangs.
- `scripts/scheduled-backup-runner.mjs` + daily systemd timer — replaces
  a broken builtin scheduler path with a standalone runner.
- `scripts/runtime-warmup.mjs` + systemd `Before=memphis.service` —
  pre-loads Ollama LLM + embedding models, GPU with auto-CPU-fallback.

## Operators

This release targets local, single-operator deployments. The systemd
unit ships with sane defaults (memory limits, `Linger=yes`, hourly
chain-sweep timer).

```bash
# Install
git clone https://github.com/Memphis-Chains/memphis.git
cd memphis && npm install && npm run build
node dist/infra/cli/index.js memphis-self-test

# Run as a service (systemd user)
systemctl --user enable --now memphis-warmup.service memphis.service
```

A healthy `memphis.service` reports:

```
blocks: 10,290
chains: 10
pulse_health: healthy
provider: minimax
embed_mode: ollama
```

## From 1.12 → 1.13 (breaking changes)

- `canSelfModify` is now **computed** (`capable && canSelfRecover`), not
  hardcoded to `false`. This is the unlock for tier-0 self-modification;
  further unlocks require a clean 24-hour SLO window.
- `agents.json` no longer lists draft cognitive subpersonas without
  runtime identifiers. If you scripted against the v1.12 agent list,
  re-read `AUTHORS.md` and pin to the actual identifiers.
- Git-ignore rules tightened for private operator artifacts (per-operator
  docs, drafts, backups). These files were briefly staged in the v1.13
  cycle; they are now correctly excluded.

## Known issues

- `backups.enabled` reports `false` in the runtime self-governance view
  because the *builtin* scheduler path is broken. This is bypassed by
  the new standalone `memphis-scheduled-backup.timer` — backups
  **do** run nightly. The flag will be flipped in a future release when
  the builtin path is repaired (tier-2 source fix).
- LLM model swap: the default `OLLAMA_MODEL` is now
  `qwen2.5:0.5b`. The previously used `qwen2.5-coder:3b` crashes its
  Ollama runner on GTX 960-class GPUs. If you have a beefier card,
  set `OLLAMA_MODEL=qwen2.5-coder:7b` in `.env` and run
  `scripts/runtime-warmup.mjs` to verify.
