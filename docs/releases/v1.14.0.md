# Memphis v1.14.0 — Release Notes

**Release date:** 2026-11-23
**Tag:** `v1.14.0`
**Since:** `v1.13.5` — 316 commits (MEASURED on the release branch at
`2e93c84fc1f`; the published tag holds **251** commits in `main`'s graph,
because the `--squash` policy collapsed the branch's **324** authored
commits into one)

The release where the cross-arm rules get their owners. Nothing here is a
promise: every number below was measured on the operator's host, and the
repository carries the artefacts and the gates that keep them true.

---

## TL;DR

- **One owner per rule, one artefact per cross-boundary rule, two runners.**
  The chain-name vocabulary, the bridge's export vocabulary and the tool
  contract each had three or four owners; each has one now, plus an artefact
  and a gate that fails when they drift.
- **The runtime counts live chains.** Measured on the operator's host: the
  status answered 11 510 blocks in 14 directories where the live chains hold
  11 234 in 12 — the gap was one archive counted as if it were the chain.
- **A new chain:** `proposals`, with the command that fills it.
- **The public chat has a consent gate per block** and reads a bounded
  window instead of 36 MB of JSON per request.
- **The error ledger** (`docs/design/MEMPHIS-ERROR-LEDGER.md`): ten open
  errors with a measurement each, six rejected hypotheses, and "developed"
  written as seven checks that can be run rather than admired.
- **The tarball ships every module the CLI loads.** The first publish attempt
  failed: the package did not carry `scripts/backup-manifest.mjs`, which the
  compiled CLI imports at startup, so every command died with "Cannot find
  module". The omission list in `package.json` is now checked by a gate that
  discovers the omissions instead of trusting the list.
- **One gate that was green where it was measured.** The public chat's
  readiness test asked the real basal service on 127.0.0.1:8000, so it passed
  on this host and failed on every CI runner. The check is injected now, and
  the test pins all three readiness cases.

## The three owners

### 1 · The chain-name vocabulary

"What is a chain called?" had four owners and three answers. The native
runtime asked *"does the name end in `.backup-<digits>`?"* — so an archive
stamped with a date was a live chain, an archive stamped with a number was
not, and the rotation's `.archives` directory was a chain.

Now one module owns it (`crates/memphis-paths/src/chain_names.rs`), the
bridge serves it to TypeScript, the projection writes an artefact of 36 cases
and the TypeScript mirror from the owner's own answers, and both arms are
checked against it. The cockpit no longer lists `.archives` as a chain.

### 2 · The bridge's export vocabulary

The bridge's vocabulary was declared in three places and compared by nobody:
the binary exported 37 functions, the manifest named 34, and nine of those
names were spellings the bridge never exported. One table owns it now, and
the gate checks the table against the crate's own declarations — so the
bridge exports 39 functions and every one of them can be named from
TypeScript.

### 3 · The tool contract

The native surface advertised 23 tools whose schemas were a second copy of
the TypeScript registry, and the copies had drifted. The native catalog is a
projection of the registry now: every tool projected, the `DIVERGENCES` table
empty (all five were closed), one fixture read by both arms.

## What an operator will notice

- **The runtime's status is honest.** `chains` and `blocks` count the live
  chains. The audit still counts archives — verifying an archive is its job
  — and says "scannable" rather than "live".
- **The public chat asks for less.** The catalog reads a 1 000-block window
  of the non-journal chains and the journal in full, one block at a time.
  Consent is read per block, not per chain.
- **The chains stop growing on their own.** Rotation works, the live chain
  continues its archive under the same write lock the append path takes,
  and four archives are kept per chain.
- **The operator's to-do is a field, not a phrase.** `context.operatorTodo`
  — an item addressed to the operator can no longer be read as the agent's
  assignment.
- **Pasting into the cockpit no longer carries escape codes** into the
  input buffer.

## What is still open — measured, not hidden

- **The embed profile (E-02).** The semantic half works in a process that
  has the service's environment and fails everywhere else, and the dim
  default is written in four places. The failure is reported
  (`degraded: true` plus the message), but the defaults are wrong and a
  fresh install reproduces the broken profile.
- **The wedge (E-05).** 15 recovery turns still wait for an operator who
  cannot clear them from where he is: the path wants a local TTY and the
  operator's passphrase, and the TUI has no recovery command.
- **The chain taxonomy.** The name rule is shared; the chain list is not.
  The native runtime counts `_quarantine` as a chain (0 blocks today).
- **E-07 / E-08 / E-09**: the clean drain that exits 0, the backup
  retention that stops when the drill fails, and the bridge's payload types.

## Installing

```bash
npm install -g @memphis-chains/memphis@1.14.0
```

The GitHub release carries the npm tarball and a `SHA256SUMS` file; the
workflow publishes to the GitHub Packages npm registry as well. See
[`docs/dev/RELEASE-PROCESS.md`](../dev/RELEASE-PROCESS.md) for the signing
setup.

**Operator-facing note:** this release does not change the vault format, the
chain format's location, or the way the operator's passphrase works. It
changes what the runtime REPORTS and which rule decides what a chain is.
