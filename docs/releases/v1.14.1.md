# Memphis v1.14.1 — Release Notes

**Release date:** 2026-11-24
**Tag:** `v1.14.1`
**Since:** `v1.14.0`

One ledger entry closed: the embed profile. The dimension and the index
path had defaults from two different eras, and four owners that disagreed.

Every number below was measured on the operator's host. The release carries
the artefact and the gate that keep it true.

---

## TL;DR

- **The embed profile has one owner.** The index path, the dimension, the
  model, the source of each and the verdict are answered by ONE module
  (`crates/memphis-embed/src/profile.rs`). The operator, the N-API bridge
  and every TypeScript surface ask it.
- **The dimension follows the index on disk.** `RUST_EMBED_DIM` → the
  dimension recorded in the index → the local deterministic width, which is
  reached only when there is no index to contradict it. The `32` that was
  hard-coded in four places was never an embedding dimension; it was the
  width of the placeholder embedder.
- **The mismatch that was not the cause is gone.** A shell used to answer
  dim 32 against an index that holds 768. It now answers 768 (from the
  index) and the verdict names the cause that IS there: no provider is
  configured for this process.
- **A fresh install no longer pins the profile.** `memphis init` and the
  onboarding wizard stopped writing `RUST_EMBED_DIM=32` into the `.env`.
- **The mode vocabulary has one owner on both sides.** The config schema's
  enum, the doctor's whitelist and the wizard's validity check were three
  hand-written copies of the same ten words; they now come from the
  projection.
- **One gate that failed on its first CI run**, and found a hole in its own
  artefact: the first version carried this machine's directory layout in a
  sentence of prose, so the gate said "stale" on every other runner.

## What was wrong, measured

The ledger's E-02, measured 2026-11-23 at the recall surface:

| process | index it reads | dim | result |
| --- | --- | --- | --- |
| the service (full `.env`, systemd `EnvironmentFile`) | `embed/bge-m3-20261106/index-v1.json` | 1024 | `mode: semantic`, `degraded: false`, 3 hits |
| without it (any script, any spawned process, the CLI) | `embed/index-v1.json` (stale, 82 KB) | 768 on disk vs **32** configured | `embed_search: index_dimension_mismatch: disk_dim=768 config_dim=32` |

The `32` was written in four places (`src/infra/http/health.ts:405`,
`src/infra/tensors/status.ts:68`, `src/infra/cli/commands/setup.ts:293`,
`src/infra/cli/onboarding-wizard.ts:68`) and in the config schema as
`.default(32)`. The index-path default was written twice with two roots —
HOME-based in TypeScript, data-dir-based in Rust.

## The rule now

```
index path   = RUST_EMBED_PERSIST_PATH  |  <data_dir>/embed/index-v1.json
dimension    = RUST_EMBED_DIM  |  the dimension recorded IN THE INDEX  |  the local width
model        = RUST_EMBED_PROVIDER_MODEL  |  unknown
verdict      = ok | no-provider | no-index | dimension-mismatch
```

Measured after, 2026-11-24, the owner asked for the two processes this host
has:

| process | dimension | verdict |
| --- | --- | --- |
| the service | **1024** (from `env`) | `ok` |
| a bare shell | **768** (from the index) | `no-provider` |

## A claim the code no longer supported

The comment in `src/infra/http/health.ts` said the provider's vector was
"truncated to the configured dim without warning". That was true on
2026-10-25 and stopped being true on 2026-11-06, when the provider path
became strict (PR #749). The comment survived 18 days and was quoted in the
error ledger — it is now the measured behaviour.

The two ways a wrong width costs are not the same, and the code now says
which is which:

- with a **provider** configured, the provider's own width is the truth and
  the provider path is strict: a 1024-wide answer to a 32-wide
  configuration is a **loud** error — "ollama returned embedding dimension
  1024, expected 32" — and every embed fails;
- with the **local** embedder the vector is always exactly `dim` wide, so
  nothing fails at all: a 32-wide query against a 768-wide stored vector
  scores 0.0 (`cosine_similarity` returns 0.0 for unequal lengths), and
  recall matches nothing, **silently**.

## What this release does NOT claim

The dimension of a **provider** is still unknown to the owner: it has no
model→width table, and a guess would be a wrong width on every call. Where
there is no index, the profile says `no-index` instead of pretending to
know the provider's width.

The next item in the ledger's queue is **E-09** — the bridge's payload
types, which do not exist on the TypeScript side.
