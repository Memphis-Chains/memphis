# Memphis — Y1 Roadmap 2026-05 → 2027-05 (reality-grounded)

> **Status.** Approved 2026-04-23; v3.1 refactor 2026-04-23 same evening integrates federation primitives. This is the binding Y1 roadmap.
>
> **History.** Supersedes earlier v1 (approved 2026-04-21, archived at `docs/roadmap/archive/Y1-v1-2026-04-21.md`). Iterated v2 → v3 after codebase reality recon, then v3 → v3.1 after integrating existing federation + Agora design findings (Matrix trust tiers in `src/federation/`, Agora design in `ROADMAP_FOR_SORT_BRANCHES.md`). v3.1 does NOT re-open approved scope decisions — it routes Kartograf distribution + multi-instance sync through existing federation primitives instead of inventing parallel transport/trust.
>
> **Principle.** Every deliverable maps to a concrete file path. Every new capability is either (a) extension of an existing component, or (b) green-field with one named new file/crate. No speculative infrastructure. Quarterly scope = one solo builder with periodic AI pairing.
>
> **Core middle-path bet (v3.1).** Memphis ships Kartograf publicly (HF Hub + GH Release + USB) AND lets operators sync checkpoints privately between their own Station/Nomad machines via existing Matrix federation. Public-tier Agora (reputation + stake + DHT) is explicitly Y2+ and does not block Y1. Kartograf CLI surfaces are Agora-ready (`--source` flag) so later extension is additive.
>
> **Review cadence.** Last week of each quarter. Each review updates N-table + files `docs/roadmap/<year>-Q<n>-review.md`. Integration sync gates (Q1/Q2/Q3/Q4 exit tests) validated quarterly.

## Three simplification moves vs v2

1. **Kartograf runtime = ONNX Runtime, not Python subprocess.** Train in Python once (off-box or on GTX 960). Export to ONNX. Ship `.onnx` file. Inference in Node via `onnxruntime-node` (Apache-2.0, stable-platform). Zero new Python runtime for operators. Multi-head supported natively by ONNX.
2. **RLM sandbox moves to Y2 research.** Building a Python sandbox + AST check + resource limits + recursion audit is 3-6 months of its own work. Collides with Memphis core stabilization. Existing `src/providers/dynamic-router.ts` + direct RAG is good enough for Y1. RLM deserves its own dedicated year.
3. **Kartograf v1 = embedding + zone only.** Mutability / safety-boundary / advisory-generator heads defer to v2 (Y2). Gets Kartograf shipped on one thesis (semantic retrieval + chain routing), not four. v1 usefulness: tier-0 embedding (replaces Ollama nomic as default) + chain-name suggestion.

## Non-negotiables (v3.1 refactor adds 4 → 12 total)

1. **Every new capability maps to one named file or crate.** No "new system" without a path.
2. **Vault never enters training corpus.** Hard invariant — allowlist paths + denylist `~/.memphis/vault/**` + secret-pattern regex (same patterns as `scripts/secret-scan.sh`) + provenance metadata per sample.
3. **Apache-2.0 only.** No GPL/LGPL inputs. Third-party weights verified (`modernbert-base` = Apache-2.0 confirmed).
4. **Kartograf ≤ 4 GB VRAM at inference.** ModernBERT-base FP16 ≈ 300 MB; head of slack.
5. **Self-modify hard blocks stay path-based.** Kartograf is advisory, not authoritative.
6. **Training happens once per checkpoint.** Not on every git push, not per-PR. Watrowanie cadence = every other night with eval gate.
7. **Cloud is escape, not default.** Kartograf initial train tries GTX 960 (LoRA + head only). Cloud H100 activated only if eval threshold missed.
8. **RLM and multi-head Kartograf both deferred to Y2.** Don't sneak them into Y1 scope.
9. **Kartograf distribution + sync rides federation primitives, no parallel transport.** Private-peer sync uses `src/federation/matrix/*` + HMAC (N14). Public releases use HF Hub + GH Release (not federation). Agora tier (Y2+) plugs into same `--source` CLI shape. One trust model, not three.
10. **Kartograf checkpoint = signed block.** Ed25519 signed via existing `crates/memphis-core/src/signature.rs` keypair. Rides on existing `system` chain with `data.type='kartograf_checkpoint_published'`. No new chain type, no new schema.
11. **Public → private contamination refused by default.** `memphis kartograf install --source hf-hub` defaults to `--as-baseline=true` (checkpoint stored as recovery baseline, not promoted to active). Active checkpoint swap requires explicit `--force-active` and survives regression gate. Locally-tuned checkpoints (from Watrowanie or federation sync) outrank public releases unless eval proves otherwise.
12. **Agora is Y2+, Y1 leaves door open.** `memphis kartograf install --source <name>` accepts `hf-hub|file|github-release|federation` in Y1; `agora` returns "not implemented, Y2+ scope" but rejects gracefully (no crash, no silent fallback). Same for `publish`.

**C-bis. Private-tier Kartograf sync (N41 NEW, depends on N14).**

Operators with >1 Memphis instance (Station trains overnight, Nomad serves inference) can push/pull Kartograf checkpoints between their own peers without going through public registries.

- `src/federation/kartograf-sync.ts` (new) — push/pull logic atop existing `MatrixTransport` + N40 envelope.
- Protocol (all federation-primitive; no parallel transport per non-negotiable #9):
  1. Station signs checkpoint envelope (N40) with Ed25519.
  2. HMAC-SHA256 over sync envelope (N14).
  3. Matrix file upload of the model artefact via `mxc://` URI on the operator's own homeserver (Matrix supports large-blob content via media repository — this is the same primitive Element clients use for file attachments, not a side channel).
  4. Matrix DM to peer with envelope metadata: `{mxc_uri, sha256, envelope_signature, hmac}`.
  5. Peer downloads from `mxc://` URI (same Matrix auth + TLS as the envelope message), verifies SHA256 + Ed25519 + HMAC before activation.
- Escape hatch (only when federation transport itself unavailable): envelope JSON copied via USB/SSH by operator, `memphis kartograf install --source file --envelope <path>` — same verification, carrier swap. This is the manual-mode fallback, not the primary path.
- CLI: `memphis federation kartograf push --peer <id> --checkpoint <sha|latest>`, `... pull --peer <id>`, `... diff --peer <id>`, `... peers-heads` (lists what each peer has).
- Non-goal: automatic-everything. Operator must invoke `pull`; no silent background sync (predictability > magic).
- Divergence: if peers diverge (each has own Watrowanie history), `diff` reports; operator picks winner explicitly. No auto-merge.
- Failure modes: peer unreachable → clear error, no retry loop. Checkpoint fails verify → reject + log. Operator can always `uninstall` + start fresh.
- Escape hatch: if N14 slips, N41 ships in "manual-only" mode (operator copies envelope JSON via USB, no federation transport) — same protocol, different carrier.
