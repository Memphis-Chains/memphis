Co to jest · What it is

Memphis to osobisty runtime dla jednego operatora.

Nie SaaS. Nie platforma. Nie startup szukający inwestora. To środowisko uruchomieniowe, które instalujesz lokalnie na Linux/macOS/WSL2, uruchamiasz jednym poleceniem, i od tej pamięci agenta zależy Twoja codzienna praca.

⚠

Pamięć, której nie da się podważyć

7 Łańcuchów, każdy blok z hashem poprzedniego. Wstrzyknij cokolwiek w środek — Łańcuch się rozjedzie i Memphis to zauważy.

🔒

Sekrety w zaszyfrowanym sejfie

AES-256, Argon2id, rotacja master key. Każdy odczyt zostawia ślad. Klucze nigdy nie lądują w pliku .env.

🛡

Guard przed destrukcją

Każdy rm i mv przechodzi przez HALT registry. Zatrzymany zasób blokuje operację, zanim ją wykona.

Co Memphis robi

  • Pamięta decyzje w 7 content-addressed Łańcuchach
  • Trzyma sekrety w encrypted vault (pepper + master-key rotation)
  • Ma 59 natywnych tooli dostępnych przez MCP
  • Integruje się z agent-plugins-spec (Cursor, OpenCode, Mavis-compatible)
  • Guarduje destrukcyjne operacje przez HALT-aware destructive ops
  • Audit chain w JSONL — każdy tool call zapisany

Czego Memphis NIE jest

  • NIE jest SaaS-em ani platformą z chmury
  • NIE jest wrapperem na cokolwiek (M3/M2.7 są opcjonalne)
  • NIE telemetruje — zero outbound calls w default install
  • NIE szuka pieniędzy, equity, ani partnerów inwestycyjnych
  • NIE wymaga internetu do działania (lokal-first)
  • NIE jest vendor-locked — audytowalne end-to-end

HALT-aware destructive ops · co wyróżnia Memphis

Skill, którego inne runtime'y nie mają.

Powstał po incydencie z 2026-09-22, gdy agent peer usunął plik objęty council-request HALT bez koordynacji. Memphis nie ufa agentom — nawet sobie. Każdy rm, mv, git rm jest sprawdzany przed wykonaniem.

Jak to działa

HALT registry w ~/.memphis/halt/ — jeden plik JSON na wstrzymany zasób. Plik = SHA-256 ścieżki, więc deterministic, no path conflicts.

Pre-flight guard (check.sh) — wywoływany przed destrukcyjnymi operacjami. Jeśli argument pasuje do halted resource → exit 1, operacja zablokowana.

Audit JSONL w ~/.memphis/audit/halt/events.jsonl — każde sprawdzenie (pass/block/bypass) zapisane. Append-only.

Bash hook — opcjonalny DEBUG trap w ~/.bashrc guarduje automatycznie. Dla nie-bash agentów: explicit halt_rm / halt_mv.

Cron integrity — memphis-halt-integrity.timer codziennie 09:00 sprawdza czy halted files istnieją. Wykrywa jeśli inny agent usunął resource bez zgody.

Bypass conscious — HALT_BYPASS=1 HALT_BYPASS_REASON='...' rm file loguje powód i przepuszcza. Anti-hubris: bypass jest logowany ale nie cryptographically gated.

Integracja · agent-plugins-spec

Plugin format, nie proprietary fork.

Memphis opakowuje się w Agent Plugins v1.0.0 spec — otwarty standard z TSC zawierającym Amazon, Cursor, Microsoft, OpenAI, Vercel. To znaczy że Memphis capabilities są kompatybilne z każdym conformant client bez vendor lock-in.

Co to daje

  • Memphis = plugin dla Mavis (minimax-code)
  • Te same skille działają w Cursor, OpenCode, innych conformant clients
  • Plugin capabilities: tools, hooks, skills, agents
  • Otwarty governance przez GitHub Discussions
  • Zero lock-in — jeśli Memphis nie pasuje, plug-out i tyle

Zainstaluj u siebie · Quick start

Pięć kroków. Pięć minut. U siebie na dysku.

Zero konta, zero chmury, zero telemetrii. Wymagany Node 22 (instalator sprawdza i podpowiada), Linux / macOS / WSL2. Cały runtime ląduje w ~/memphis, pamięć w ~/.memphis.

01
Zainstaluj
Node 22, Rust, skille. Do ~/memphis.
$ curl -fsSL https://raw.githubusercontent.com/Memphis-Chains/memphis/main/scripts/install.sh | bash
02
Pierwszy raz
Passphrase operatora, hasło sejfu, tożsamość, pierwsze zapisy do łańcuchów.
$ memphis init
03
Podepnij MiniMax
Klucz API ląduje w zaszyfrowanym vault, nie w .env. Klucz zdobierz na platform.minimax.io.
$ memphis provider add minimax --api-key <twoj-klucz>
04
Uruchom
Usługa w tle (Linux/WSL) i natywny kokpit Rust TUI. Na macOS: npm run dev w terminalu.
$ memphis service install
$ memphis service restart
$ memphis tui
05
Sprawdź
Ile bloków w łańcuchach, ile sekretów w sejfie, jaki provider odpowiada. To jest memphis health.
$ memphis health

Pytania · FAQ

Najczęstsze pytania, uczciwe odpowiedzi.

Nie. Memphis to open-source runtime, który instalujesz lokalnie na Linux, macOS lub WSL2. Nie ma chmury, nie ma konta, nie ma telemetrii. Jedynym miejscem, gdzie Twoje dane opuszczają maszynę, jest wywołanie do wybranego providera modelu — i to robisz świadomie.

Jedna komenda: curl -fsSL https://raw.githubusercontent.com/Memphis-Chains/memphis/main/scripts/install.sh | bash. Potem memphis init i memphis tui. Wymagany Node 22 — instalator sprawdza i podpowiada. Reszta w sekcji Quick start wyżej.

memphis provider add minimax --api-key TWOJ_KLUCZ. Klucz trafia do zaszyfrowanego vaulta, nie do pliku .env. Providerzy działają w kaskadzie: jeśli MiniMax padnie, Memphis automatycznie przechodzi do następnego z listy, a w ostateczności do lokalnego fallbacku.

Wszystko lokalnie w ~/.memphis — łańcuchy, vault, stan runtime. Zero outbound calli w domyślnej instalacji, zero analytics, zero telemetrii. Możesz skopiować katalog i przenieść na inną maszynę.
