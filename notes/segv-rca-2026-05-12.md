## TL;DR

The crashed thread was executing **`memphis_napi::embed_shutdown`** — the Rust shutdown callback for the global `EMBED_PIPELINE: OnceLock<Mutex<EmbedPipeline>>` singleton. Stack jumped through a NULL pointer (`#0  0x0` with `rip=0x0`) while checking `Once::is_completed` via `OnceLock::get()`. Same class of bug as **PR #588** (Kartograf ONNX session vs V8 teardown race), but for the embed pipeline instead — and possibly newly exposed by #588's reordering of the stopFns array.

**Previous memory guess was wrong.** Memory `project_segv_v8jit_2026-05-12.md` claimed the culprit was *"UAF from a Node native binding (likely `memphis_exec` child_process)"*. Stack trace says **EmbedPipeline shutdown**, not exec. Memory needs correction.

## What this means

When V8 invoked `embed_shutdown_c_callback` (Memphis bootstrap's stopFn for embed pipeline), the function tried to read the `EMBED_PIPELINE` global's OnceLock state. The atomic load resolved to a NULL function pointer — which only happens if:

1. The OnceLock's vtable was relocated / freed (loader unmapped the library segment before the callback ran), OR
2. The `EMBED_PIPELINE` static itself was clobbered (UAF — Rust statics shouldn't UAF, so this is unlikely unless V8 GC ran a finalizer that touched it), OR
3. **More likely:** the binding pointer cached in V8 (the FunctionCallbackWrapper's user data) was already a stale pointer to a torn-down callback, and tail-calling through it landed on 0x0.

The **same fix shape as PR #588** likely applies: ensure `embed_shutdown` runs in the explicit shutdown ordering BEFORE V8 starts releasing native handles. The Kartograf fix added a stopFn entry; embed needs the parallel entry if it doesn't already have one.

### A4. Look for `napi_add_env_cleanup_hook` or `napi_add_finalizer` usage in crates/memphis-napi
If embed-shutdown is registered as a V8-managed cleanup hook (not as a Memphis stopFn), then PR #588's pattern needs to migrate to it: explicit drain via Memphis stopFn **before** V8 starts running its own cleanup queue.

## Recommended fix (sketch)

```typescript
// src/app/bootstrap.ts — add to stopFns BEFORE kartograf-onnx-session
{
  name: 'embed-pipeline',
  stop: async () => {
    const napi = await import('../infra/storage/rust-embed-adapter.js');
    if (typeof napi.shutdownEmbedPipeline === 'function') {
      await napi.shutdownEmbedPipeline();
    }
  },
},
```

(Sketch assumes `shutdownEmbedPipeline` exists or can be added as a TS-side wrapper around the NAPI `embed_shutdown`. Implementer should verify the actual NAPI export name in `rust-embed-adapter.ts`.)
