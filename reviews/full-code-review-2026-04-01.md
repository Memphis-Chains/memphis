# Full Code Review - 2026-04-01

## Scope

Reviewed `/home/memphis/memphis` as the project root, with emphasis on runtime-critical and security-sensitive paths:

- HTTP server and routes
- gateway and in-process tool execution
- memory and recall flows
- storage and embedding integration

## Findings

### High

1. In-process memory recall can leak other users' memory

- File: `src/gateway/memory-client.ts`
- Lines: 30-43
- Issue: recall results are filtered by `userId`, but if no matching hit exists the code falls back to the unfiltered top results.
- Impact: canonical chat surfaces can inject another user's recalled memory into the current conversation context.

2. Explicit operator tool policies are bypassed on the HTTP/chat runtime path

- Files: `src/infra/http/server.ts`, `src/gateway/tool-executor.ts`, `src/gateway/authorization.ts`, `src/mcp/server.ts`
- Issue: the in-process executor used by `/v1/chat/generate` resolves policy from the soul manifest only and is not given the SQLite permission repository, while the MCP server does honor explicit operator overrides.
- Impact: `memphis config tools deny ...` is not reliably enforced for tool calls triggered through the HTTP/chat runtime.

### Medium

3. Durable memory IDs collide across chains

- File: `src/infra/memory/durable-memory.ts`
- Lines: 38-68
- Supporting file: `crates/memphis-embed/src/pipeline.rs`
- Issue: autogenerated memory IDs always use the `journal-*` prefix regardless of the actual chain, and the embed store uses upsert semantics keyed by ID.
- Impact: writes from non-journal chains can overwrite embeddings from journal entries with the same block index.

4. Chain-scoped recall is ignored on the semantic path

- File: `src/mcp/tools/recall.ts`
- Lines: 85-128
- Issue: the `chain` filter is passed to exact and chain-fallback search, but not to semantic search, and semantic hits do not carry chain metadata for post-filtering.
- Impact: `/api/recall` with a chain filter can still return hits from other chains when semantic search succeeds.

5. The dashboard is wired against an API contract it cannot successfully call

- Files: `src/infra/http/auth-policy.ts`, `src/infra/http/server.ts`
- Issue: `/api/status` requires auth by default, but the dashboard fetches it without an auth header. The dashboard also expects `uptimeSec` and `chain.bridgeLoaded`, while the backend returns `uptime` and `rustBridgeLoaded`.
- Impact: the dashboard can fail even when the service itself is healthy.

## Follow-up Interpretation

This review points to serious architectural gaps in Memphis, especially at security and integration boundaries.

### Critical Security Concerns

1. Cross-user memory leakage

- `src/gateway/memory-client.ts` falls back to unfiltered recall results when no `userId` match exists.
- This breaks multi-user memory isolation.

2. Tool policy bypass on HTTP/chat runtime

- The HTTP/chat runtime uses the soul manifest path only and does not honor the SQLite permission repository used by MCP.
- This weakens the expected Tier 0/1/2 access-control model for tool execution.

### Medium Architectural Concerns

3. Memory ID collisions across chains

- Multiple chains can generate `journal-*` embedding IDs.
- This allows one chain's embedding write to overwrite another chain's embedding at the same index.

4. Chain filter bypass on semantic recall

- `src/mcp/tools/recall.ts` does not enforce the requested chain on the semantic search path.
- A chain-scoped recall request can therefore return hits from other chains.

5. Dashboard/API contract mismatch

- The dashboard expects fields that the backend does not return, and it calls `/api/status` without auth even though that route is protected by default.
- This makes the dashboard unreliable even when the service itself is healthy.
