Why Memphis exists

sovereignty, translated into runtime control

Memphis was born from Oswobodzeni, but its public promise must be operational. Sovereignty here means control over infrastructure, data, secrets, boundaries, and the operator loop. In a world of rented AI, Memphis is the stack you can actually own and run on your own hardware.
Your machine, your memory, your vault, your operator loop.
System pillars

four things the site must prove fast

Four things the Memphis front must prove fast — memory, vault, observability, operator control. Not just sound good. Show the system under the hood.
memory

append-only continuity

Memory is a system layer, not a prompt add-on. Every entry is SHA-256 linked and auditable.

vault

sealed secret discipline

Keys and tokens live in vault. Not scattered across scripts and env files.

obs

health and logs

Memphis communicates state through health, metrics and structured logs — not silence.

operator

tool use with control

Runtime works for the operator, not instead of the operator.

Runtime surfaces

multiple ways in, one system underneath

Memphis should be readable for both developers and operators. The public page must clearly show that Memphis is a full runtime with multiple work surfaces — not just a repo with a readme.

TUI cockpit

Native terminal cockpit for working with memory, vault, sessions and system state.

HTTP + MCP

Integrations via API and agent transports — without locking into one work channel.

Remote surfaces

Telegram and other surfaces as system inputs, not replacements for the runtime itself.
